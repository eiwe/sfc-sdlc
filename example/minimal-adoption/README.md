# Minimal artifact example

This fictional Python CLI (`notekeep`) demonstrates a populated intent/spec/plan
chain, ADR, handoff and concise changelog. It is a document example, not a runnable
application or a certified live harness session.

The tagging artifacts illustrate an already accepted manual workflow. Read the
existing authorization and continue its scope; do not ask for it again simply
because the session or harness changed. A real adopted project also receives
WORKFLOW.md, ROLES.md, TESTING.md, REVIEW.md, the controller/shared guards, selected
harness adapters, CI, owners and the versioned installation record.

For the example, read HANDOFF.md → AGENTS.md → `docs/changes/tagging/`, implement
against the accepted plan, add meaningful tests, finish changelog/handoff, and
obtain independent verification/review before integration. The listed application
commands show what an adopted project supplies; they cannot be run from this
document-only folder.

Controller fixture tests in the source repository exercise autonomous artifact
progression, repair, escalation and resume without model credentials. The installed
[workflow guide](../../skills/adopt/templates/WORKFLOW.md) explains operator policy
and the difference between a local cooperative trial and authoritative deployment.
